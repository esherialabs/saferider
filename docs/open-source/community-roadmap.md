# Community roadmap

SafeRide uses public GitHub issues and the
[SafeRide Open Source Roadmap](https://github.com/orgs/esherialabs/projects/3)
project board.

## Board states

- **Todo** — accepted public work that is unscheduled or ready for a contributor.
- **In Progress** — actively owned work, including issues with a linked open pull
  request.
- **Done** — merged into the canonical public repository with verification.

Labels, milestones, linked pull requests, and issue comments retain the finer
`ready`, `in review`, and `blocked` distinctions without publishing sensitive
security, survivor, partner, or operational information.

## Labels

`good first issue`, `help wanted`, `documentation`, `accessibility`, `mobile`,
`api`, `web`, `testing`, `on-device-ai`, `privacy`, `security`, and `blocked`
provide the primary routing. Security vulnerabilities never use public issues.

At least five maintained `good first issue` items should be available whenever
the backlog supports them. Each must have a bounded change, owned files,
synthetic verification, and a clear definition of done.

## Release milestones

Milestones group public work by tagged release. A release is not complete until
its notes, license/community files, checks, coverage evidence, checksum ledger,
and reproducible source-build record are public. Product/store/UNICEF approval
is tracked separately and must not be inferred from a GitHub milestone.
